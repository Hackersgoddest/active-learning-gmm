## 4.1  What "revealing a label" does to the E-step

Ordinarily, every point's responsibility comes from Bayes' rule, using
whatever the model's *current* parameters say (Lesson 2, Section 2.4):

$$
r_{nk} = \frac{\pi_k\,\mathcal{N}(\mathbf{x}_n\mid\boldsymbol\mu_k,\boldsymbol\Sigma_k)}
{\sum_{j=1}^{K}\pi_j\,\mathcal{N}(\mathbf{x}_n\mid\boldsymbol\mu_j,\boldsymbol\Sigma_j)}.
$$

This is an **estimate**: the best guess the model can make given the data and
its current parameters. Suppose for one point it currently comes out
$r_n = (0.6, 0.4)$: unsure, though not badly so.

Now suppose an oracle reveals the *true* label for that one point: it was
in fact generated by component 2. We don't recompute $r_n$ from the formula
above anymore; we **fix it**, for the rest of the fit:

$$
r_n \leftarrow (0, 1) \quad\text{(clamped, never recomputed by the formula again)}.
$$

Every other, still-unlabeled point keeps using the ordinary formula, unchanged.
This mix, some rows hard-fixed and the rest still soft, is called **clamped EM**
(or semi-supervised EM). The M-step formulas themselves (the weighted averages
for $\pi_k$, $\boldsymbol\mu_k$, $\boldsymbol\Sigma_k$, Lesson 3) don't change
at all; they just now receive this mixed set of responsibilities as input.

**Why clamp instead of just "trust it a little more"?** Because the formula
above is only ever a guess *because* we don't know the truth. Once we do know
it, there's nothing left to estimate for that point; using anything other
than $(0,1)$ would mean deliberately ignoring information we were just handed.

## 4.2  Why clamping one point moves the whole model

This is the part that's easy to miss: we only directly touched *one* point's
responsibility. But $\boldsymbol\mu_k$ and $\boldsymbol\Sigma_k$ are weighted
averages **over every point** (Lesson 3, Section 3.3):

$$
\boldsymbol\mu_k = \frac{1}{N_k}\sum_{n=1}^{N} r_{nk}\,\mathbf{x}_n,
\qquad N_k = \sum_{n=1}^N r_{nk}.
$$

**Worked example.** Three points $A, B, C$ currently have responsibility to
component 2 of $0.4, 0.3, 0.9$. Right now, $\boldsymbol\mu_2$ is a weighted
average of $A,B,C$ using those three numbers as weights. Suppose $A$'s true
label is revealed to be component 1, not 2. Clamping sets $A$'s responsibility
to component 2 to exactly $0$ (and to component 1 to exactly $1$). Recomputing:

$$
\boldsymbol\mu_2^{\text{new}} = \frac{0\cdot\mathbf{x}_A + 0.3\,\mathbf{x}_B + 0.9\,\mathbf{x}_C}{0+0.3+0.9}
$$

$A$'s pull on $\boldsymbol\mu_2$ is gone entirely, and $\boldsymbol\mu_1$ just
gained $A$'s full weight (it only had $0.6$ of $A$ before, now it has $1.0$).
Both component means moved. On the **next** E-step, $B$ and $C$ (who were
never told anything) get *recomputed* using these new, shifted means. Nothing
new was revealed about $B$ or $C$, yet their responsibilities can change
anyway, purely because the cluster shapes moved underneath them.

**This is the whole mechanism that makes active learning possible at all.** If
revealing one label only ever affected that one point, it wouldn't matter
*which* point you asked about; they'd all help equally. Because it reshapes
the shared parameters, *which* point gets revealed actually matters.

## 4.3  The leverage argument behind uncertainty sampling

If clamping reshapes $\boldsymbol\mu_k,\boldsymbol\Sigma_k$ by changing how
much weight a point contributes, then **how much a single clamp can move the
model depends on how much that point's weight changes**, i.e., on how far
its responsibility was from one-hot *before* clamping.

Compare two points, both about to be clamped to component 1:

- **Confident point**, $r_n=(0.95,0.05)$. Clamped to $(1,0)$: change of
  $+0.05 / -0.05$. Barely moves anything, since it was already almost fully
  counted toward component 1.
- **Uncertain point**, $r_n=(0.5,0.5)$. Clamped to $(1,0)$: change of
  $+0.5/-0.5$, ten times larger. It was splitting its weight evenly; now it
  fully commits.

**Uncertainty sampling's whole premise**: pick the point with the highest
entropy $H_n$ (closest to an even split) to query next, because that point has
the most "leverage" to move: clamping it changes the weighted averages the
most, so (the hypothesis goes) it should teach the model the most per
question asked.

## 4.4  The blind spot this creates (→ RQ5)

Uncertainty sampling only ever looks at $H_n$: how *unsure* the model
currently looks about point $n$. RQ1 found a case where the model is
**confidently wrong**: a lopsided fit where EM is *more* sure of a lopsided,
incorrect split than it would be of the honest one. That point has **low**
entropy: it looks confident, not uncertain, so uncertainty sampling would
never choose to query it, even though clamping it might correct the model's
worst mistake far more than clamping some borderline point would.
"Looks uncertain" and "would be useful to correct" are not guaranteed to be
the same thing. Not tested yet; this is exactly what RQ5 is for.
